0這份文件解決什麼問題

需求是「生成很多假資料」。但盤點之後的結論是：直接灌資料，灌出來的數字會是錯的——而且錯得不明顯。畫面上的額度長條還是有長度、應收帳冊還是有金額、心理師酬勞還是有數字，只是每一個都偏掉一點，而且會愈用愈偏。所以順序必須是：先對齊 → 再梳理 → 最後才生成。

最能說明問題的一個例子心理師酬勞對三種薪酬模式套同一條「金額 × 抽成率 ＋ 保底」。回饋制（教支中心那種）的意思是鐘點費由心理師自己向機構請領、診所抽的那份要由心理師回繳，所以它對酬勞是扣項。舊寫法把它當成正的抽成，等於診所倒過來付一筆錢出去，金額還是最大的那種錯。這在畫面上完全看不出來——數字是正的、格式是對的、只是方向反了。

1.1 哪張表是「事實」

session_records。不是 appointments。這個區別是整套設計的關鍵：

表角色為什麼
appointments意圖「打算在這個時間、這個診間、跟這位心理師見面」。可以改時間、改診間、取消——它是計畫，會變
session_records事實「這場真的發生了，金額是這樣，抽成率是這樣」。日報表、月報表、應收帳冊、核銷、酬勞全部只讀這張。報價快照跟著它走，所以事後改預約不會改到已經發生的帳
inst_enrollments額度個案在某個方案的剩餘量。三態中只有「已預留」「已使用」落地，「已預約」永遠即時數

1.2 額度三態：為什麼「已預約」不落地

恆等式：quota_limit + extended_count = used_count + reserved_count + COUNT(booked 預約)

「已預約」不存成欄位，而是每次查 status='booked' 的預約數量。這樣做的好處是不可能對不起來——預約被建立、取消、刪除時，計數自動跟著變，不需要記得同步一個計數器。代價是每次要多一個 COUNT 查詢，值得。

這裡有一個非直覺的坑依 01 §C3 定案，未到的預約 status 維持 booked、不轉 cancelled（要留著對帳）。同時 release() 又已經把那一格還進 reserved。所以 booked 的計數必須排除 check_in_status='no_show'，否則同一格會同時被算成 booked 和 reserved，恆等式憑空多 1，畫面顯示「已用 1/3」但其實一次都沒用掉。這正是本輪修掉的 bug 之一。

2.1 費率規則引擎

inst_rate_rules 依 sort_order 排序，先匹配先贏，空條件 {} 永遠命中（當預設）。條件支援 7 個 key，值可以是純值或 {"gte":n} 這類比較。

一個必須用測試釘住的設計rule_matches() 對不認得的條件 key 是寬容跳過，不是判定失敗——立意是避免一個打字錯誤癱瘓整個報價。代價是：規則寫錯 key 不會噴錯，而是靜默變成命中全部，價錢就錯了。所以有一支測試斷言「所有 when_json 的 key 都在 field_map 裡」，把靜默錯價變成紅燈；不變量檢查器也有同一條。

3.1 配號系統

新增 number_sequences(scope, last_seq) 表，配號是單一原子語句：

UPDATE number_sequences SET last_seq = last_seq + 1
 WHERE scope = :scope RETURNING last_seq

Postgres 把該列鎖到交易結束，第二個交易排隊等待，所以不會發重複號碼；交易 rollback 時號碼跟著還回去，不留空號。scope 字串本身帶日期（receipt:20260908:C），所以「配哪一天的號」純粹由呼叫端傳入的 on_date 決定——這正是灌歷史資料需要的能力。

順手修掉的一個現成地雷next_receipt_no() 是在 build_session_record() 的 db.add() 之前被呼叫的。舊的 COUNT 寫法在「同一天連續建多筆」時會連續數到同一個數字，配出重複號碼撞 unique。一天本來就有十幾場，灌歷史資料必踩。

5.1 寫入通道：依「有沒有跨表不變量」決定

資料類通道理由
使用者／診間／機構／合約／方案／費率ORM 直寫沒有不變量，純參考資料
預約、報到、未到、取消、額度轉移、核銷收納呼叫既有 service三態恆等式只活在 adapter.py 裡。生成器自己重寫一份保證會跟本尊漂移
歷史帳冊、收據、酬勞ORM 直寫service 的時間戳綁 now()，而這裡要產生的是去年十月的紀錄
HTTP API完全不用被過去日期防呆與 auth 擋住
回填時間怎麼做到的perform_check_in() 與 perform_cancel() 有一個 keyword-only 的 now 參數，刻意不放在端點簽名上——FastAPI 會把多出來的參數當成 query string，等於開一個「從 HTTP 就能偽造報到時間」的洞。留在函式那一層，HTTP 永遠拿不到，生成器卻用得到。

5.4 假個資

姓名／地址／電話自己組，不引入 Faker——這支腳本要能在診所那台 Windows 機器直接跑，少一個套件少一個坑。身分證用檢查碼正確的假號，因為病歷號會取末兩碼、activate_case() 會擋沒有身分證的個案。號碼隨機，不對應任何真人。
