# CheerPsy 資料庫結構與資料轉換規範

> 用途：舊資料轉入新系統（PostgreSQL 16）的完整參考。
> 對應程式版本：migration head = `z2a1b2c3d4e5`（伴侶案付款方）。
> 後端：FastAPI + SQLAlchemy 2.x + Alembic；資料庫 PostgreSQL 16。
> ⚠️ 本文件以實際 model 程式碼為準（`apps/api/app/models/*.py`）。匯入前請先 `alembic upgrade head` 建好所有資料表。

---

## 0. 快速摘要（先看這個）

- **主鍵** `id`：所有表皆為 `Integer` 自增（PostgreSQL `SERIAL`/identity）。可指定明確值匯入，但匯入後**務必重設序列**（見 §6）。
- **時間欄位**：`DateTime(timezone=True)` → PostgreSQL `timestamptz`，**一律以 UTC 儲存**。台灣時間需 +08:00 換算回 UTC（或帶時區字串讓 PG 自動換算）。
- **日期欄位**：`Date` → `date`（無時區）。
- **金額**：`Numeric(10,2)`（最多 99,999,999.99）。新台幣常為整數，仍以兩位小數存。
- **身分證**：**加密儲存**（`national_id_encrypted` = bytea；`national_id_hmac` = 查找用雜湊）。**不可直接塞明文**，必須用系統加密函式（見 §5.1）。
- **列舉值**：DB 端多為純字串（無 DB enum 約束），但程式只認特定值（見 §1.3）。匯入時務必用正確字串。
- **匯入相依順序**：見 §2。先 `users`/`institutions`/`rooms`，再 `cases`，再預約與帳務。

## 1. 通用約定

### 1.1 欄位型別對照

| SQLAlchemy | PostgreSQL | 說明 |
|---|---|---|
| `Integer` | `integer` | 含主鍵與 FK |
| `String(n)` | `varchar(n)` | 有長度上限，超過會被拒 |
| `Text` | `text` | 無長度上限 |
| `Numeric(10,2)` | `numeric(10,2)` | 金額 |
| `Numeric(4,2)` | `numeric(4,2)` | 抽成率（0.70 = 70%） |
| `Boolean` | `boolean` | true/false |
| `Date` | `date` | 年月日 |
| `DateTime(timezone=True)` | `timestamptz` | UTC |
| `LargeBinary` | `bytea` | 加密身分證 |
| `TSTZRANGE` | `tstzrange` | 預約時段（含起訖、防衝突） |
| `JSONB` | `jsonb` | 稽核前後值 |

### 1.2 外鍵與刪除行為

- 多數 FK **無 ON DELETE**（預設 `NO ACTION`）→ 被引用的母資料不能先刪。
- 例外（`ON DELETE CASCADE`）：`case_institution_quotas.case_id`、`quota_templates.institution_id`。
- `quota_templates.created_by` 為 `ON DELETE SET NULL`。

## 2. 匯入相依順序（由上而下）

```
1. users                      （帳號；被幾乎所有表的 created_by/therapist_id 參照）
2. institutions               （機構）
3. rooms                      （診間）
4. cases                      （個案；含一般案與伴侶案。伴侶案的成員須先存在）
5. couple_members             （伴侶案 ↔ 成員 連結）
6. quota_templates            （機構額度範本，選用）
7. case_institution_quotas    （個案機構扣打）
8. appointments               （預約；參照 case/therapist/room/quota）
9. session_records            （日結帳冊；參照 appointment/case/therapist/room）
10. invoices                  （收據；參照 appointment）
11. claim_batches             （核銷案；之後再回填 session_records.claim_batch_id）
12. therapist_payouts         （心理師酬勞）
13. payout_details            （酬勞明細；參照 payout + session_record）
14. petty_cash                （零用金）
15. product_sales             （其他販售）
16. invitations / notifications / reminder_log / audit_log（輔助表，通常不需轉舊資料）
```

> 伴侶案特例：`cases` 內 `case_type='couple'` 的列，其 `couple_members` 連到的兩位成員必須是**已存在的** `case_type='individual'` 列。建議先匯一般個案，再匯伴侶案列，最後匯 `couple_members`。

## 4. 業務規則與不變量（轉資料必讀）

### 4.1 角色與 user_code
- 每個帳號**都要** `user_code` 且唯一。前綴：admin `A` / accountant `C` / staff `S` / therapist `T`。
- 預約編號、核銷編號會引用 `user_code`，缺漏會導致建立預約失敗。

### 4.2 個案兩階段
- Stage 1 建檔：給 `temp_seq`、`status='initial'`、`case_number=NULL`。
- Stage 2 轉正式：補齊身分證/生日/電話後產生 `case_number`、`status='ongoing'`。
- **轉舊資料時**：歷史個案多半已是正式案，直接給 `case_number`、`status='ongoing'`、`temp_seq=NULL` 即可（不必模擬兩階段）。

### 4.3 伴侶案模型
- 伴侶案 = `cases` 一列（`case_type='couple'`、`case_number='C…'`、無身分證、`status='ongoing'`、有共同 `therapist_id`）。
- 兩位真人 = 各自 `individual` 個案（各有身分證、可單獨預約）。
- `couple_members` 連結（2 列）。
- **機構合療**：核銷以人為單位 → 合療預約 `case_id` = 付款成員、`couple_case_id` = 伴侶案；扣的是該成員的 `case_institution_quotas`。
- **自費合療**：合療預約 `case_id` = 伴侶案、`couple_case_id` = 伴侶案（或 NULL），費用記伴侶案。

### 4.4 預約編號 / visit_seq / 房間衝突
- `appointment_number` = `R-{YYYYMMDD}-{user_code}-{當日該心理師第N筆:03d}`。
- `visit_seq` = 該 `case_id` 既有預約數 + 1。
- `time_range` 用 `tstzrange`；同一 `room_id` 時段重疊會被 `EXCLUDE USING GIST` 擋下（僅 `booked`/`executed`）。匯入歷史預約若同房同時段重疊會失敗，需先清洗。

### 4.5 結算（T+1 / 即時materialize）
- 「日結」= 把**結束時間已過**（含 20 分鐘提前量）的 `booked` 預約轉成 `session_records`，並把預約 `status` 改 `executed`。
- 寫入快照：`commission_rate_used`（讀當下心理師抽成，空值→0.70）、`funding_source`（讀當下 case）、`receipt_no`（`R{YYYYMMDD}{每日序號:04d}`）、`payment_status='unpaid'`。
- **外出保底**（`session_type='outdoor'`）：`bonus = max(0, min(amount, 1000) − amount×rate)`，補心理師抽成至 `OUTPATIENT_MIN_FEE=1000`，診所不墊錢（總額不足時全額讓利、診所領 0）。存入 `outcall_bonus`/`outcall_note`。
- **轉舊資料**：歷史「已完成」場次應直接建 `session_records`（並可把對應 `appointments.status` 設 `executed`），不要依賴自動結算。務必自己填好 `commission_rate_used`、`receipt_no`、`payment_status`。

### 4.6 機構扣打扣減
- 結算機構場時，原子性 `UPDATE case_institution_quotas SET used_count = used_count + 1 WHERE id=? AND used_count < total_count`；扣不到（額度用完）就跳過該場待人工處理。
- **轉舊資料**：`used_count` 請依歷史已使用場次數正確帶入，避免與匯入的 `session_records` 重複計算。

### 4.7 核銷案編號與狀態機
- 編號：自費 `S{cycle}-{case_number}-{YYYYMM}`（cycle: once→O, monthly→M, multiple→X）；機構 `I-{institution.code}-{YYYYMM}`；同名重複後綴 `-2`、`-3`。
- 狀態機：
  - **自費**：`collecting` → `received`（收款；終態）。
  - **機構**：`collecting` → `ready`（所有紀錄「心理師已繳 AND 行政已核對」，或機構免文件/已豁免）→ `submitted` → `received`。
- 機構案 `received` 時，內含紀錄 `payment_status` 由 unpaid/claiming → `claimed`。

### 4.8 付款狀態生命週期（`session_records.payment_status`）
- 預設 `unpaid`。
- 自費收款 → `paid`（`paid_at` 填時間）。
- 機構核銷案到帳 → `claimed`。
- 報表口徑：「已收/請款」= `paid`+`claimed`；「未收」= `unpaid`(+保留值 `claiming`)。

### 4.9 心理師酬勞（payout）
- 以 `therapist_id` 彙總某月 `session_records`：酬勞 = Σ(有效金額×抽成 + outcall_bonus)。
- `therapist_payouts`（月）+ `payout_details`（對應 session_record）。可重跑（idempotent）：`paid` 不動、`pending` 重算。

### 4.10 零用金結餘
- `balance_after` = 前一筆結餘 ± 本筆（支出為扣）。**匯入時請依日期/建立序列累計算好**，否則款項追蹤會錯。

## 5. 資料轉換實務

### 5.1 身分證加密（最重要）
`national_id_encrypted` 是 **AES-GCM 密文**（格式：`nonce(12 bytes) + ciphertext`），金鑰 = `sha256(ID_ENCRYPTION_KEY)`。`national_id_hmac` = `HMAC-SHA256(key, 明文)` 的 hex。

**務必使用與正式環境相同的 `ID_ENCRYPTION_KEY`**，否則日後無法解密。建議用系統函式批次轉換：

```python
# 在 apps/api 環境下執行（需設好 ID_ENCRYPTION_KEY 環境變數）
from app.utils.encryption import encrypt_national_id, hmac_national_id
enc = encrypt_national_id("A123456789")   # → bytes，存入 national_id_encrypted (bytea)
hm  = hmac_national_id("A123456789")      # → hex str，存入 national_id_hmac
```

- 直接寫 SQL 時，bytea 可用 `\x` 十六進位字面值（把上面 `enc` 轉 hex）。
- 沒有身分證的個案（如伴侶案）兩欄都留 NULL。
- 正式案號 `case_number` 末兩碼來自身分證末兩碼；若沿用舊案號則直接給定即可，不需再經產生器。

### 5.2 時間與時區
- 所有 `timestamptz` 欄位請帶時區。台灣時間建議寫成 `'2026-03-05 14:00:00+08'`，PG 會存成 UTC。
- `Date` 欄位（session_date、birth_date…）直接 `'2026-03-05'`。

### 5.3 金額與列舉
- 金額存兩位小數；不要存千分位字串。
- 列舉欄位只能用 §1.3 的值（小寫英文）。中文標籤是前端轉的，DB 一律存英文代碼。

### 5.4 序列重設（重要）
指定明確 `id` 大量匯入後，序列不會自動前進，下次新增會撞主鍵。對每個有自增主鍵的表執行：

```sql
SELECT setval(pg_get_serial_sequence('users','id'),        COALESCE((SELECT MAX(id) FROM users), 1));
SELECT setval(pg_get_serial_sequence('institutions','id'), COALESCE((SELECT MAX(id) FROM institutions), 1));
SELECT setval(pg_get_serial_sequence('rooms','id'),        COALESCE((SELECT MAX(id) FROM rooms), 1));
SELECT setval(pg_get_serial_sequence('cases','id'),        COALESCE((SELECT MAX(id) FROM cases), 1));
SELECT setval(pg_get_serial_sequence('appointments','id'), COALESCE((SELECT MAX(id) FROM appointments), 1));
SELECT setval(pg_get_serial_sequence('session_records','id'), COALESCE((SELECT MAX(id) FROM session_records), 1));
-- 其餘表同理；另外 cases.temp_seq 使用獨立序列：
SELECT setval('cases_temp_seq_seq', COALESCE((SELECT MAX(temp_seq) FROM cases), 1));
```

### 5.5 建議匯入方式
1. `alembic upgrade head` 建好結構。
2. 用「暫存 staging 表 + SQL `INSERT … SELECT`」或 Python 腳本（呼叫上面加密函式）逐表匯入，依 §2 順序。
3. 機構扣打 `used_count`、零用金 `balance_after` 等**累計欄位**要算好。
4. 匯入後重設序列（§5.4）並跑檢核（§6）。
5. 建議先在本機 `docker compose up` 試一輪，確認無誤再上正式。

## 6. 匯入後檢核 SQL

```sql
-- 1. 列舉值是否乾淨
SELECT DISTINCT status FROM cases;          -- 應只在 initial/ongoing/paused/closed/lost
SELECT DISTINCT funding_source FROM cases;  -- self_pay/institution
SELECT DISTINCT payment_status FROM session_records;

-- 2. 案號唯一且格式正確
SELECT case_number, count(*) FROM cases WHERE case_number IS NOT NULL GROUP BY 1 HAVING count(*)>1;

-- 3. 機構案必須有 institution_id
SELECT id,name FROM cases WHERE funding_source='institution' AND institution_id IS NULL;

-- 4. 心理師都有 user_code
SELECT id,name,role FROM users WHERE user_code IS NULL;

-- 5. 伴侶案結構：每個 couple 應有 2 名成員，且成員皆為 individual
SELECT couple_case_id, count(*) FROM couple_members GROUP BY 1 HAVING count(*)<>2;

-- 6. 機構扣打不應超用
SELECT id, used_count, total_count FROM case_institution_quotas WHERE used_count > total_count;

-- 7. 帳冊金額/抽成快照齊全（已執行場次）
SELECT count(*) FROM session_records WHERE commission_rate_used IS NULL;

-- 8. 同房同時段衝突（理論上會被 GIST 擋，但確認一下）
SELECT a.room_id, count(*) FROM appointments a
WHERE a.status IN ('booked','executed') AND a.room_id IS NOT NULL
GROUP BY a.room_id, a.time_range HAVING count(*)>1;

-- 9. 身分證可正確解密（抽樣，於 apps/api 用 decrypt_national_id 驗證若干筆）
SELECT id, octet_length(national_id_encrypted) FROM cases
WHERE national_id_encrypted IS NOT NULL LIMIT 5;   -- 長度應 = 12(nonce)+密文
```
